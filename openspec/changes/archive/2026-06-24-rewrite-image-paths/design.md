## Context

After the `always-rebuild-and-serve-static` change, `--mds` mode serves source files via `/source/*` route. Markdown images generate `<img src="relative/path.png">` tags. The browser resolves these relative to the current page URL, producing requests like `/screenshots/photo.png` instead of `/source/screenshots/photo.png`. Result: all images return 404.

The existing `rewrite_md_links()` function already post-processes HTML to rewrite `.md` links to `.html`. Adding image path rewriting follows the same pattern.

## Goals / Non-Goals

**Goals:**
- Make relative image paths in markdown work correctly with `/source/` route
- Handle all common image path patterns: `./img.png`, `../img.png`, `subdir/img.png`
- Skip absolute URLs (`https://...`), data URIs (`data:image/...`), and already-prefixed paths (`/source/...`)

**Non-Goals:**
- Changing the server routing (Option B approach)
- Handling `<video>`, `<audio>`, or `<source>` tags (future enhancement)
- Rewriting CSS `url()` or JS fetch paths

## Decisions

### D1: Add `rewrite_image_paths()` as a separate function (not extending `rewrite_md_links()`)

**Choice**: Create a dedicated `rewrite_image_paths()` function alongside `rewrite_md_links()`.

**Rationale**: Separation of concerns — link rewriting and image rewriting are logically different operations. Easier to test, maintain, and extend independently. Both are called sequentially in `render_body()`.

### D2: Use regex to match `src="..."` attributes

**Choice**: Regex pattern `src="([^"]*)"` to capture image source values.

**Rationale**: Consistent with the existing `MD_LINK_RE` approach. Simple and sufficient for standard HTML generated by pulldown-cmark. No need for a full HTML parser.

### D3: Only rewrite relative paths

**Choice**: Skip paths starting with `/`, `http://`, `https://`, `data:`, or `#`.

**Rationale**: Absolute URLs and data URIs should not be prefixed. Paths already starting with `/` are absolute and should be left as-is (user explicitly chose an absolute path).

### D4: Call after `rewrite_md_links()` in `render_body()`

**Choice**: Execute image rewriting as the last post-processing step.

**Rationale**: Image rewriting doesn't affect link rewriting or heading ID injection. Running it last ensures all other transformations are complete.

## Risks / Trade-offs

- **[Over-rewriting]** Could prefix a path that shouldn't be prefixed (e.g., a CDN URL without protocol). → Mitigation: Check for `://` prefix to detect protocol-relative URLs.
- **[HTML structure]** Regex-based approach assumes standard `<img src="...">` format. → Mitigation: pulldown-cmark generates consistent HTML, so this is safe.
- **[video/audio]** Not handled in this change. → Mitigation: Can add similar rewriting for `<video src="...">` and `<audio src="...">` in a follow-up.
